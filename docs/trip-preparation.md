Existing newer-record, reset/course/alternative and cross-tab protections still apply, including rechecks before restore and departure. ## Initial Page-only Undo Release

The deleted reading record is held byte-for-byte in page memory only; successful undo restores its original guide/task, timestamp, disclosure flags and position. Preparation, bookmark and decision records are never written. No new storage key, backend request or migration is introduced. Focus moves from the disappearing forget control to undo, then to the restored Continue reading link. Status feedback is localized; failures never claim success and keep a valid undo available for retry.

An undo has no countdown, but is discarded on pagehide, reload or fresh navigation, including departure into BFCache. A reset/changed course or alternative invalidates it; a new reading value (even unreadable) wins over the older one. The action rechecks current storage immediately before restoring and never replaces an existing value. Checklist-only changes do not invalidate undo and are preserved. Clear also rechecks the displayed record before deleting, so a stale control does not silently remove a newer other-tab record. ## Storage Boundaries

`tripcompass.trip-prep.v1` contains only version, known course ID, alternative ID and five booleans. Parsing is length-limited, validates the supported version and values, and discards extra properties. Reading never creates or rewrites state. Starting or changing preparation writes locally. No dates, free text, identity, new analytics, AI requests or server storage are added.

The English and Korean pages share the key on the same origin/browser profile. There is no cross-device sync or offline download. On blocked storage, progress remains on the current page with an explicit not-saved notice; navigation can lose it. A corrupt or unsupported stored record is not overwritten until the user starts again. Cross-tab and browser-history restores refresh readable state; memory-only changes are retained on the current page.

Reset requires an inline confirmation and removes only the preparation key. Bookmarks, language choices and comparison-board data remain. If deletion fails, the UI does not claim success or hide the current preparation. Last-write-wins applies to simultaneous edits of the same field; this is not collaborative editing.
